DATA / SECURITY / LIMITS — PLEASE READ
- Keep the same deployed domain to retain that domain's existing browser storage.
  Study data from another domain or localhost is separate and needs its existing export/import tools.
- Your original entrance screen is preserved. Its client-side password is NOT server authentication.
  Anyone can inspect public frontend assets. For a private website use Vercel Deployment Protection
  or a proper authenticated backend. No claim of production access control is made by the entrance.
- Keys are never hardcoded into the repository or saved by the server-side application code.
  Remembered keys live in browser localStorage, which is not encrypted. Do not use shared browsers.
- Provider/API billing is separate from a consumer chat subscription. xAI Grok/direct DeepSeek and
  many other model endpoints are paid. OpenRouter free-model availability is not guaranteed.
- A hosted proxy cannot create provider capacity, remove rate limits, or guarantee account access.
- Image/PDF-answer tasks need a vision-capable provider model. Use smaller selections if the hosted
  body limit is reached (the site checks the limit before posting). Non-Gemini PDF batches are capped
  at 12 selected pages; available payload/model limits may require fewer. No document pages are
  silently dropped. Gemini direct requests remain subject to Google's own limits/CORS.
- PIB scope is the official English PIB Delhi archive, all ministries; regional-office archives are not
  silently claimed. Source retrieval still depends on upstream government websites.
- Yojana loads the EXACT English issue listed in the official Publications Division public archive.
  That public archive may lag publication. Missing issues are reported, not replaced by another month.
  Upload your English issue PDF if necessary. Scanned pages without extractable text require OCR.
- Other-provider schemas are provided in system instructions; original client validators still reject
  invalid output. Model-generated content is not guaranteed factually perfect.
